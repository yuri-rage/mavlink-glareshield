# Tests

Glareshield's tests: TypeScript suites run by `npm test`, Python checks of the bridge, and scripts that run against
ArduPilot SITL. MAVLink framing, decoding and encoding are also checked against **pymavlink** (golden vectors).

## Running

```bash
npm test                    # every tests/*.test.ts, in parallel (about 11 s)
npm test -- mission fence   # only files whose name contains any of these
TEST_JOBS=4 npm test        # at most 4 at once (default: one per CPU)
```

`npm test` is `scripts/run-tests.mjs`: it finds the test files itself (a new `tests/*.test.ts` runs with no list to
update), runs them in parallel with the local `tsx`, prints PASS/FAIL per file, and at the end the output of any that
failed. Each file is a plain script that exits non-zero on failure, so one can also be run alone:
`npx tsx tests/cockpitLayout.test.ts`.

CI (`.github/workflows/ci.yml`) runs `npm test`, the bridge checks below and the build on every pull request, and on
`master` deploys only when all pass.

## The suites

| Area | Files |
| :--- | :--- |
| MAVLink protocol | `mavlink.test.ts` (framing, CRC, parser recovery, MAVFTP, `.pck` / `.dat` unpackers, telemetry store), `golden.test.ts` (against pymavlink's `vectors.json`), `dialect.test.ts`, `inspector.test.ts`, `storeBatching.test.ts` |
| Links | `transport.test.ts` (WebSocket, Web Serial, WebUSB, reconnects, the silent-link watchdog), `safety.test.ts` (in-progress command acks, parameters across connections, import warnings), `vehicleRoster.test.ts` (several vehicles on one link) |
| MAVFTP | `ftp_ardupilot.test.ts`: against a simulator following ArduPilot's `GCS_FTP.cpp` (reply `seq = request + 1`, resend cache, one open file per session), on clean and lossy links. It, not the mock bridge, is the one to trust for sequence handling. |
| Missions | `missionDraft`, `missionFiles` (`.plan` / `.waypoints` / `.dat` round trips), `missionPath` (splines), `missionPlanStore`, `missionProfile`, `missionSummary`, `waypointRadius`, `rallyDraft`, `rallySupport`, `fenceDraft`, `fenceControl`, `guidedActions`, `homeCache`, `lastVehicle`, `inputUnits` |
| Telemetry and widgets | `widgets.test.ts` (the custom widget engine: value pipeline, sampler, composites, relays, command presets, sanitising imports), `batteries`, `esc`, `adsb`, `gimbal`, `terrain`, `pidTuning`, `displayAltitude`, `statusMessages` |
| Parameters and logs | `paramCatalog`, `paramCompare`, `logs` (onboard logs), `tlog`, `tlogRecorder` |
| Dashboard | `cockpitLayout`, `cockpitStore`, `cockpitWide` (Cockpit tabs: layout rules, editing, the wide layout) |
| Other | `offlineTiles`, `whep` (WebRTC video), `voiceEngine`, `buildInfo` (build stamp and update check), `regressions.test.ts` (QGC plans as QGroundControl writes them, the 720-byte RTCM edge, version polling) |

`fixtures/` holds sample data some suites read (a Rover parameter-defaults sample).

## Python checks of the bridge

Install once: `pip install -r bridge/requirements-test.txt` (the bridge's dependencies and pymavlink). Each starts the
bridge itself:

```bash
npm run test:bridge-security # WebSocket Origin allowlist (including Origin: null); the NTRIP client can't relay or inject
npm run test:bridge-udp      # in UDP mode, commands go only to the vehicle when another GCS shares the port
npm run test:mock            # mock bridge telemetry, decoded by pymavlink
npm run test:follow          # the map's follow-vehicle loop (no packages needed)
npm run test:review          # all four
```

To check a bridge that's already running: `python3 tests/check_mock_bridge.py --url ws://127.0.0.1:56781`.

## Against ArduPilot SITL

`sitl/*.sitl.ts` drive a real ArduPilot SITL (actions and `COMMAND_INT`, fence upload and breach prediction, mission
planning round trips, splines). They aren't part of `npm test`: each file's header gives the SITL command line and how
to run it.

## Golden vectors

`vectors.json` holds reference packets generated by pymavlink (2.4.50, `ardupilotmega` dialect). Regenerate them only
when adding decoders or moving to a newer dialect:

```bash
npm run test:vectors         # python3 tests/gen_vectors.py
```

They cover the `crc_extra` table, the decoders (`HEARTBEAT`, `SYS_STATUS`, `ATTITUDE`, IMUs, `GLOBAL_POSITION_INT`,
`GPS_RAW_INT`, `VFR_HUD`, `BATTERY_STATUS`, `AUTOPILOT_VERSION`, `STATUSTEXT`, `PARAM_VALUE`, `COMMAND_ACK`, the
mission messages), sentinels (unknown heading, unmeasured battery), zero-truncated MAVLink 2 frames, every encoder
method, and MAVFTP packing and parsing.
